## 1. Project Overview

Nexus is a real-time messaging platform built with modern web technologies. Users can search for others, create 1-on-1 or group conversations, and exchange messages in real-time.

### Key Features
- User authentication (JWT-based)
- User search and discovery
- Real-time messaging via Socket.IO (JWT-authenticated WebSocket)
- Optimistic UI updates
- Responsive design (mobile-first)
- Conversation management

## 2. Architecture Philosophy

**Code as Architecture** - Every line must be justified, typed, and maintainable.

### Core Principles
1. **Type Safety**: Zero `any` types - every variable explicitly typed
2. **No Unused Code**: Every import, variable, and function must be utilized
3. **Separation of Concerns**: Controllers → Services → Database
4. **Explicit over Implicit**: Function signatures, return types, prop interfaces all declared
5. **Incremental Implementation**: Build features step-by-step, test each layer
6. **Performance First**: Optimistic updates, debouncing, efficient queries

### Prohibited Patterns
- ❌ `any` types without explicit justification
- ❌ Inline business logic in components
- ❌ Direct database calls from frontend
- ❌ Unused imports or dead code
- ❌ Unhandled promise rejections

## 4. Database Schema

### Tables

#### `public.users`
```
id            BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
created_at    TIMESTAMPTZ NOT NULL DEFAULT NOW()
name          VARCHAR NULL
email         VARCHAR NOT NULL UNIQUE
pass          VARCHAR NOT NULL
avatar_url    TEXT NULL
last_seen     TIMESTAMP WITHOUT TIME ZONE NULL
status        TEXT NULL
```

#### `public.conversation`
```
id            BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
created_at    TIMESTAMPTZ NOT NULL DEFAULT NOW()
type          TEXT NULL
name          TEXT NULL
```

#### `public.conversation_participants`
```
id                BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
created_at        TIMESTAMPTZ NOT NULL DEFAULT NOW()
conversation_id   BIGINT NULL REFERENCES conversation(id) ON UPDATE CASCADE ON DELETE CASCADE
user_id           BIGINT NULL REFERENCES users(id) ON UPDATE CASCADE ON DELETE RESTRICT
joined_at         TIMESTAMP WITHOUT TIME ZONE NULL DEFAULT NOW()
```

#### `public.messages`
```
id                BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
created_at        TIMESTAMPTZ NOT NULL DEFAULT NOW()
sender_id         BIGINT NULL REFERENCES users(id) ON UPDATE CASCADE ON DELETE RESTRICT
content           TEXT NULL
conversation_id   BIGINT NULL REFERENCES conversation(id) ON UPDATE CASCADE ON DELETE CASCADE
```

### Relationships
- `conversation` ←→ `conversation_participants` (one-to-many, cascade on delete)
- `users` ←→ `conversation_participants` (one-to-many, delete restricted)
- `conversation` ←→ `messages` (one-to-many, cascade on delete)
- `users` ←→ `messages` (one-to-many via `sender_id`, delete restricted)

## 6. API Endpoints

### Conversations
```
GET    /api/conversations           - List user's conversations
POST   /api/conversations           - Create new conversation
  Body: { participantIds: number[], type: 'dm' | 'group', name?: string }
  Response: { conversationId: number, conversation?: ConversationWithDetails }
```

### Messages
```
GET    /api/messages/:conversationId  - Fetch messages for conversation
POST   /api/messages/:conversationId  - Send message
  Body: { content: string }
  Response: { message: MessageWithSender }
```

### Users
```
GET    /api/users/search?q=<query>    - Search users by name/email
  Response: { users: UserProfile[] }
```

### Authentication
- Auth routes (below) do not require a token.  
- All other endpoints require `Authorization: Bearer <jwt_token>` header.

### Auth
```
POST   /api/auth/signup             - Create a user
  Body: { email: string, name: string, pass: string }
  Response: { message: string, user, token }

POST   /api/auth/login              - Log in
  Body: { email: string, pass: string }
  Response: { message: string, user: { id, email, name }, token }
```

## 7. Type System

### Architecture
```
database.ts (Base Layer)          api.ts (Derived Layer)
├── User (full schema)      →     ├── UserProfile = Pick<User, ...>
├── Conversation            →     ├── UserDisplay = Pick<User, ...>
├── Message                 →     ├── MessagePreview = Pick<Message, ...>
└── ConversationParticipant →     └── ConversationWithDetails (composed)
```

### Key Types

```
// lib/types/api.ts
export type UserProfile = Pick<User, 'id' | 'name' | 'email' | 'avatar_url' | 'status'>;

export type UserDisplay = Pick<User, 'id' | 'name' | 'avatar_url' | 'status'>;

export type MessagePreview = Pick<Message, 'content' | 'created_at' | 'sender_id'>;

export interface MessageWithSender extends Pick<Message, 'id' | 'content' | 'created_at' | 'sender_id'> {
  sender: Pick<User, 'id' | 'name' | 'avatar_url'>;
}

export interface ConversationWithDetails extends Pick<Conversation, 'id' | 'created_at' | 'type' | 'name'> {
  participants: Array<{ user: UserDisplay }>;
  last_message: MessagePreview | null;
  unread_count: number;
}
```

**Pattern**: Always use `Pick<>`, `Omit<>`, or `extends` to derive types - never duplicate definitions.

## 11. Common Patterns

### API Call Pattern
```
async function fetchResource(id: number, token: string): Promise<ResourceType> {
  const response = await fetch(`${process.env.NEXT_PUBLIC_API_URL}/api/resource/${id}`, {
    headers: {
      Authorization: `Bearer ${token}`,
    },
  });

  if (!response.ok) {
    throw new Error('Failed to fetch resource');
  }

  const data: ResponseType = await response.json();
  return data.resource;
}
```

### Optimistic Update Pattern
```
const handleAction = async () => {
  const tempId = `temp-${Date.now()}`;
  const optimisticItem = { tempId, ...data, status: 'sending' };
  
  // Add immediately
  setItems(prev => [...prev, optimisticItem]);
  
  try {
    const result = await apiCall();
    // Replace temp with real
    setItems(prev => prev.map(item => 
      item.tempId === tempId ? result : item
    ));
  } catch (error) {
    // Mark as failed
    setItems(prev => prev.map(item =>
      item.tempId === tempId ? { ...item, status: 'failed' } : item
    ));
  }
};
```

### Socket.IO Subscription
```typescript
useEffect(() => {
  if (!conversation || currentUserId === null) return;

  // Connect to socket and join conversation room
  try {
    connectSocket();
    joinConversation(conversation.id);
  } catch (error) {
    console.error('Failed to connect socket:', error);
    return;
  }

  // Subscribe to new messages
  const unsubscribe = onNewMessage((newMsg: SocketMessage) => {
    // Handle new message
    setMessages((prev) => {
      const exists = prev.some((msg) => msg.id === newMsg.id.toString());
      if (exists) return prev;
      return [...prev, processMessage(newMsg)];
    });
  });

  return () => {
    unsubscribe();
    leaveConversation(conversation.id);
  };
}, [conversation, currentUserId]);
```

## 12. Real-time Features

### Socket.IO Configuration
The backend uses Socket.IO with JWT authentication for secure real-time messaging.

**Backend Setup (`backend/src/socket/index.ts`):**
- JWT authentication middleware validates tokens before allowing connections
- Users join conversation rooms via `join:conversation` event
- New messages are broadcast to room via `message:new` event
- Supports typing indicators (`typing:start`, `typing:stop`)

**Frontend Setup (`frontend/src/lib/socket.ts`):**
- Singleton socket connection with reconnection handling
- Room-based message subscriptions
- Helper functions: `connectSocket`, `joinConversation`, `leaveConversation`, `onNewMessage`

## 14. Known Issues & Gotchas

### Next.js 15 cookies() API
```
// ❌ Old (deprecated)
const cookieStore = cookies();

// ✅ New (async)
const cookieStore = await cookies();
```

### Infinite Re-render Prevention
```
// ❌ Causes infinite loop
useEffect(() => {
  setLocalState(propsData);
}, [propsData]); // propsData reference changes every render

// ✅ Use props directly or memoize callbacks
const handleClick = useCallback(() => {
  // logic
}, []); // Empty deps if using functional updates
```

### Message Duplicate Prevention
```
setMessages(prev => {
  const exists = prev.some(msg => !isOptimistic(msg) && msg.id === newMessage.id);
  if (exists) return prev;
  return [...prev, newMessage];
});
```

## 15. Development Workflow

### Adding a New Feature

1. **Define Types** (`lib/types/api.ts`)
2. **Create Service** (`backend/src/services/`)
3. **Create Controller** (`backend/src/controllers/`)
4. **Create Route** (`backend/src/routes/`)
5. **Register Route** (`backend/src/index.ts`)
6. **Create API Call** (frontend component)
7. **Implement UI** (component with state)
8. **Test**: Manual testing in dev environment

### Adding a New Endpoint

```
// 1. Service
export class ResourceService {
  static async getResource(id: number): Promise<Resource> { ... }
}

// 2. Controller
export class ResourceController {
  static async get(req: AuthenticatedRequest, res: Response): Promise<void> {
    const resource = await ResourceService.getResource(parseInt(req.params.id));
    res.json({ resource });
  }
}

// 3. Route
const router = Router();
router.get('/:id', authenticateToken, ResourceController.get);

// 4. Register
app.use('/api/resource', resourceRoutes);
```

## 18. Architecture Decisions Log

### Why Next.js App Router?
- Server components reduce client bundle size
- Native support for async components
- Simplified data fetching patterns

### Why Express Backend?
- Full control over business logic
- Prevents direct database exposure
- Integrated Socket.IO for real-time messaging
- Can add rate limiting, caching, etc.

### Why Socket.IO over Supabase Realtime?
- JWT-authenticated connections (more secure)
- No exposed anon key on frontend
- Full control over event handling
- Room-based subscriptions for efficient message routing
- Typing indicators and presence features built-in

### Why Optimistic Updates?
- Instant user feedback
- Feels faster than waiting for server
- Graceful degradation on failure
